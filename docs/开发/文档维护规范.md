# 文档维护规范

> 状态：`CURRENT`\
> 返回：[文档索引](../README.md)

## 1. 文档职责

- `AGENTS.md`：只保存任务路由、强制边界和验证入口。
- `design.md`：系统上下文、分层、生命周期和设计不变量。
- `docs/README.md`：按问题导航，不复制专题全文。
- `docs/架构/**`：跨模块稳定事实、状态 owner 和生命周期。
- `docs/模块/**`：模块与代码路径、依赖、平台变体和测试锚点。
- `docs/开发/**`：修改方法、验证和文档治理。
- 专题文档：保存某个复杂能力的部署、安全或协议细节，例如 `chat-ai.md`。

一个事实只选择一个主要 owner；其他文档摘要并链接，避免多份 CURRENT 说明互相漂移。

## 2. 必须更新文档的变化

- 新增、删除或移动稳定 Route/模块；
- 改变根 Provider、启动、登录、登出或会话清理；
- 新增 API 边界、服务端 Route、持久化 key 或平台实现；
- 改变 Token、附件、密钥或权限安全规则；
- 改变环境变量、EAS profile、原生依赖、runtimeVersion 或发布顺序；
- 改变用户可见业务规则或失败语义；
- 设计状态从 `PLANNED`/`APPROVED` 进入 `INTEGRATED`，或被替代。

纯内部重命名若改变文档路径，也必须修复所有链接。

## 3. 写作规则

- 开头注明状态，并提供返回索引链接。
- CURRENT 只写已由源码/配置核实的行为；未来方案使用 `PLANNED`。
- 使用仓库相对路径，不写开发者机器的绝对路径。
- 不复制大段源码；只记录稳定接口、数据流、owner 和不变量。
- 不记录真实 Token、密码、API Key、用户数据或本地私有路径。
- 使用“必须/不得”描述强制边界，使用“建议”描述非强制实践。
- 日期只在事实重新核对或状态改变时更新，不因排版修改刷新。

## 4. 更新流程

1. 从 `AGENTS.md` 和本索引定位主要事实源。
2. 用代码、测试和配置验证关键陈述。
3. 检查工作区是否已有用户文档改动。
4. 修改最小必要层级；新增共享文档时同步索引。
5. 检查相对链接、源码路径、脚本名和状态词。
6. 执行 `git diff --check` 并报告这是文档变化，不声称运行时行为改变。

## 5. 完成定义

- 开发者能从需求词在两次跳转内找到主要事实源和拥有路径；
- Agent 无需读取全部 `docs/` 就能找到必须遵守的边界；
- 每个稳定模块至少有 owner、入口、外部依赖和验证锚点；
- CURRENT、PLANNED、INTEGRATED 和历史状态不混淆；
- 文档中的链接、路径、命令和配置键均可验证存在。
