# 修改路由与影响矩阵

> 状态：`CURRENT`\
> 返回：[文档索引](../README.md)

## 1. 修改前分级

| 等级         | 示例                                           | 开始前要求                              |
| ------------ | ---------------------------------------------- | --------------------------------------- |
| L0 局部      | 文案、样式、纯函数、小组件修复                 | 确认拥有路径和平台范围                  |
| L1 行为      | 页面状态、API 调用、表单、导航、持久化         | 写清输入、成功/失败、清理和测试         |
| L2 横切      | Auth、HTTP、Storage、根 Provider、Chat 流      | 阅读架构事实源并列影响矩阵              |
| L3 发布/安全 | 原生依赖、权限、runtimeVersion、API 鉴权、密钥 | 明确兼容、回滚、部署顺序和真机构建 Gate |

不要因为改动行数少而降级。一个依赖或配置的一行变化也可能属于 L3。

## 2. 影响矩阵

| 变化            | 必查影响                                                    | 必查文档/配置                         |
| --------------- | ----------------------------------------------------------- | ------------------------------------- |
| 新增/移动 Route | 所属布局、入口、参数、back、Deep Link、Web 刷新             | `src/app/**`、模块地图                |
| 根布局/Provider | 启动顺序、Splash、隐私、主题、Query、推送、Observe          | `design.md`、架构总览                 |
| Auth/Token      | hydrate、登录、401、登出、换号、缓存清理、Chat auth         | 认证生命周期                          |
| API             | base URL、Header、Envelope、错误、Query invalidation        | 架构总览、环境配置                    |
| Storage         | Web/Native 一致性、key、迁移、登出清理、容量                | 模块地图、认证生命周期                |
| Chat UI         | Streaming、取消、历史、附件、平台 UI、回退                  | `chat-ai.md`、Chat 测试               |
| Chat API        | 认证先后、成本、Body/附件限制、超时、错误泄漏               | `chat-ai.md`、API 测试                |
| 原生 package    | Expo 兼容、autolinking、prebuild、runtimeVersion、新 Binary | 配置构建与发布                        |
| 环境变量        | client/server 分类、schema、EAS profile、日志               | `env.js`、`app.config.ts`、`eas.json` |
| UI 原语         | 所有调用方、暗色、禁用、加载、无障碍、Web/Native            | UI 测试、模块地图                     |

## 3. 实施规则

1. 冻结本次问题和拥有路径，先做只读核对。
2. 选择现有 owner；只有确实不存在 owner 时才创建新模块。
3. 优先完成一个可验证的纵向切片，不同时重构无关基础设施。
4. 为边界行为增加最接近 owner 的测试，而不是只测页面快照。
5. 行为或路径变化时同步更新一个主要事实源，其余索引只摘要并链接。
6. 完成后按风险运行门禁，检查 diff 和用户已有改动。

## 4. 路由专项清单

- 是否需要在根 Stack 或子 Stack 注册？
- Route group 是否只是布局分组，公开 URL 是否符合预期？
- 参数是否在进入页面前校验，缺失/无效时如何处理？
- `router.back()` 在直接打开页面时是否有 fallback？
- 登录状态变化时是否会进入错误工作区？
- Web 刷新该 URL 是否仍能恢复页面？
- Modal/FormSheet 在 Web、iOS、Android 是否采用正确 presentation？

## 5. 停止条件

发现任务需要新增远端凭据、执行 EAS 发布、改变后端授权合同、清除用户数据或覆盖来源不明的已有
改动时，停止并向用户说明需要的授权。发现非阻断的邻近问题只记录，不擅自扩大范围。
