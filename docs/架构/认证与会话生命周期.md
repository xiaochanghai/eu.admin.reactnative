## 2. 当前状态模型

Auth Store 保存：

- `idle`：尚未完成本地恢复；
- `signIn`：存在 Token；
- `signOut`：无有效 Token或已清理会话。

Token 结构包含 `access`、`refresh` 和 `userId`，以 `token` key 存入统一 Storage。`signIn()` 必须
同时写入存储和内存 Store；`signOut()` 必须清除 Token、用户信息和内存状态。

## 3. 生命周期

```text
应用启动
  → hydrateAuth()
  → 读取 token
  ├─ 有值：signIn(token)
  └─ 无值/损坏：signOut()

业务请求
  → Axios 注入 Authorization / UUID / Platform
  → 成功：返回统一数据
  └─ HTTP 401：统一 signOut()

登录成功
  → 保存 token / userInfo
  → 根路由按 UserType 选择工作区
```

## 4. 不变量

- Token 只能经 Auth/Storage owner 读写；页面不得直接操作 `token` key。
- UI 隐藏不是授权。后端必须验证所有受保护资源，Chat API 也必须独立验证 Bearer Token。
- HTTP 日志、Toast、Observe event 和错误响应不得包含 Token、refresh token 或完整用户对象。
- 登出或换号后，旧请求、流式 Chat 和用户级缓存不得继续写回。
- 新增用户级持久化时必须定义 key、owner、迁移和登出清理时点。

## 5. 修改检查

登录或会话变化至少检查：登录成功、错误凭据、Token 损坏、401、主动登出、Web 刷新、应用冷启动、
不同 `UserType` 分流，以及 Chat 的服务端鉴权。相关 UI 测试以 `src/components/login-form.test.tsx`
为基础补充。
