# 客户端架构总览

> 状态：`CURRENT`\
> 返回：[文档索引](../README.md)

## 1. 运行时组成

应用由 Expo Router、React Native、React 19 和 Expo SDK 57 驱动。根布局装配全局 Provider，路由组
形成三个主要工作区，领域组件通过统一 API、Auth、Storage 和 Theme 基础设施协作。

```text
RootLayout
├── startup: auth/theme hydration, updates, push, observe
├── Providers
│   ├── GestureHandlerRootView
│   ├── KeyboardProvider
│   ├── ThemeProvider
│   ├── QueryClientProvider
│   └── BottomSheetModalProvider
└── Router Stack
    ├── (app)       ERP 工作区
    ├── (repair)    维修工作区
    ├── (chat)      AI 工作区
    └── root pages  登录、详情、设置、协议等
```

## 2. 依赖规则

- Route 可以依赖 Feature、Components、API 和 Lib。
- Feature 可以依赖 Components、API 和 Lib，但不得依赖具体 Route 页面。
- Components 的通用部分不得依赖具体业务页面；领域组件可以通过清晰 props 消费领域数据。
- API 可以依赖类型、Auth/Storage 和错误展示基础能力，但不得导入页面。
- Lib 不依赖具体 Feature 或 Route。

发现循环依赖时优先移动类型或纯函数到共同的低层 owner，不通过新增 barrel 间接掩盖循环。

## 3. 页面与导航

`src/app/**` 的文件系统结构定义路由。`(app)` 和 `(repair)` 使用共享 `TabLayout`，但拥有不同 tab
配置；`(chat)` 使用独立 Stack 和 `ChatWorkspaceProvider`。根 `index.tsx` 按用户类型分流。

新增页面时必须明确：所属布局、访问前提、参数类型、直接打开行为、Web 刷新行为和回退 fallback。
在没有历史栈的入口调用裸 `router.back()` 会产生未处理 GO_BACK，因此必须检查 `canGoBack()` 或
提供明确替代路由。

## 4. 数据流

- Query 数据：页面/Feature → 领域 Query/API → 共享 HTTP Client → Backend。
- 命令数据：用户事件 → Feature/页面 Handler → API → 更新或失效 Query。
- 本地会话：Storage → Auth/Zustand 或领域 Store → 页面订阅。
- Chat 流：Prompt/附件 → `ChatWorkspaceProvider` → `/api/chat` → 流式消息 Store → Conversation。

响应应在 API/Feature 边界转换为 UI 可消费形状，避免每个页面重复理解后端 envelope。

## 5. 横切生命周期

### 启动

认证和主题先恢复；Web 在首屏装配前加载项目现有 `Inter.ttf`，失败时降级到平台字体；原生字体由
`expo-font` Config Plugin 嵌入。Provider 挂载后首屏布局触发 Splash 隐藏和 app-start TTI。更新、
版本和推送在原生平台后台执行。任何新增启动任务必须避免无限 Splash，并有失败后的降级路径。

### 登录与登出

登录同时更新持久 Token 和 Auth Store。HTTP 401 触发统一登出。新增用户级缓存时必须接入登出
清理，而不是继续跨账号复用。

### 页面卸载

请求、流式生成、计时器、监听器和原生订阅必须支持取消或 cleanup；旧页面结果不得写入新会话。

### 更新与发布

OTA 只替换 JS 和资源。原生依赖、Config Plugin 或原生工程变化需要新 Binary 和兼容的
runtimeVersion。

## 6. 平台边界

Metro 依据文件后缀选择实现。共享调用方依赖一致的导出接口；Web 适配不能导入启动即调用的原生
模块，Native 适配不能读取 DOM 全局。涉及平台文件的改动至少运行 Web bundle，并在相关原生目标
做 Development/Release Build 验证。
