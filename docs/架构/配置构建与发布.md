# 配置、构建与发布

> 状态：`CURRENT`\
> 返回：[文档索引](../README.md)

## 1. 配置 owner

| 配置                                                    | 职责                                                      |
| ------------------------------------------------------- | --------------------------------------------------------- |
| `.env.development` / `.env.staging` / `.env.production` | 各环境原始值                                              |
| `env.js`                                                | 选择环境、Zod 校验、区分 client 与 build-time 变量        |
| `app.config.ts`                                         | Expo App、平台、Plugin、Update、runtimeVersion 和 `extra` |
| `eas.json`                                              | EAS Build profile、channel、环境和提交配置                |
| `package.json`                                          | 本地运行、检查、构建和 OTA 命令                           |
| `metro.config.js` / `babel.config.js`                   | Bundle、别名、NativeWind 与编译配置                       |

`APP_ENV` 缺省为 `development`。配置代码只从 `env.js` 获取经过校验的值；客户端源码从 `@env`
消费 `ClientEnv`，不得绕过 schema 读取任意构建机环境变量。

## 2. 本地命令

```text
pnpm install
pnpm run start
pnpm run start:reset
pnpm run web
pnpm run android
pnpm run ios
```

项目通过 `preinstall` 强制 pnpm。安装 Expo 生态依赖优先使用 `pnpm exec expo install`，让版本与
SDK 对齐。

## 3. EAS Profile

- `development`：Development Client，内部发布。
- `staging`：staging channel，内部发布。
- `production`：production channel，商店分发。
- `simulator`：iOS Simulator 配置，并保留 Android 配置。

构建环境由 profile 的 `APP_ENV` 决定。发布前必须核对 package/bundle identifier、版本、build
number、channel、runtimeVersion 和服务地址，不根据本地默认环境猜测。

## 4. OTA 与原生兼容

EAS Update 只能安全改变 JS 和静态资源。以下变化需要新 Binary：

- 新增、升级或移除带原生代码的 package；
- 修改 Config Plugin 或原生权限；
- 修改 Android/iOS 原生工程、Pod 或 Gradle 合同；
- 修改 JS 调用所依赖的原生方法签名。

发生上述变化时：

1. 更新 runtime compatibility 标识；
2. 运行 Expo 配置解析和依赖检查；
3. 生成并验证新的原生工程/Binary；
4. 先分发新 Binary；
5. 只向匹配 runtimeVersion 的 Binary 发布 OTA。

禁止使用旧 runtimeVersion 发布依赖新原生模块的 Bundle。`expo-observe`、MMKV、推送等均需要
Development Build 或 Release Build，不能用 Expo Go 证明可用。

## 5. Chat 部署

`src/app/api/chat+api.ts` 是服务端代码。Web 必须部署到支持 Expo server output/API Route 的环境，
静态托管无法运行它。原生应用通过 `EXPO_PUBLIC_CHAT_API_URL` 指向已部署端点。Anthropic Key 和
认证服务地址属于服务端配置；详细规则见 [Chat AI 配置](../chat-ai.md)。

## 6. 最小验证

```text
pnpm exec expo install --check
pnpm exec expo config --type public
pnpm run type-check
pnpm run test
pnpm run build:web
```

涉及 Android/iOS 时追加对应 Development/Release Build。EAS Build、Submit 和 Update 会改变远端
状态，只有用户明确要求时执行。
